# Replication Framework

Use this framework to adapt Sadhaka’s system across products without shallow visual cloning.

## Step 1: Define Invariants vs Variables

### Invariants (Preserve)
- trust-first narrative sequencing,
- premium contemplative tone,
- dark spiritual-modern token philosophy,
- single-primary-CTA hierarchy,
- proof-before-hard-ask conversion logic,
- accessibility and responsive discipline.

### Variables (Adapt)
- product category,
- audience pains and language,
- offer and CTA wording,
- proof types (testimonials, metrics, case evidence),
- navigation labels,
- feature emphasis,
- imagery subjects,
- copy intensity.

## Step 2: Create Brand Translation Brief

For the target project, specify:
1. Product and category context
2. Primary audience and emotional state
3. Trust barriers to resolve
4. Desired action and conversion constraints
5. Invariants/variables mapping

## Step 3: Build IA Blueprint

Map page sections using Sadhaka sequence logic:
- orientation,
- foundation,
- depth,
- product bridge,
- proof,
- conversion,
- objection handling.

## Step 4: Assign Component Patterns

For each section, choose:
- component type,
- copy depth,
- media style,
- CTA priority.

## Step 5: Token Translation

Keep design intent stable while adapting palette and emphasis for category fit.

Rule:
- preserve contrast and calm premium density,
- adapt accent strategy to audience/context,
- avoid over-saturation and trend-heavy UI effects.

## Step 6: Conversion Logic Check

Verify:
- one clear primary action,
- educational authority before ask,
- proof integrated before closing CTA,
- FAQ resolves highest-friction objections.

## Step 7: QA Against Scorecard

Run `qa-scorecard.md` before launch.

## Common Failure Modes

- Keeping the color palette but losing trust architecture.
- Pushing product claims before context and education.
- Introducing multiple competing CTAs.
- Replacing calm guidance with aggressive growth copy.
- Overfitting to one section and breaking whole-page narrative flow.
