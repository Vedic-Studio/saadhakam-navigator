# Design UI/UX Skill Companion — Sadhaka Brand System

Use this companion when the request requires **implementation-grade UI/UX direction** (layout, hierarchy, components, copy density, and interaction behavior), not just strategic brand framing.

## Core Intent

Translate Sadhaka’s trust-first spiritual brand into usable product and marketing interfaces that feel:
- premium,
- contemplative,
- credible,
- modern yet tradition-rooted.

## Decision Hierarchy

1. **Trust and clarity** over novelty.
2. **Educational authority** over feature hype.
3. **Single primary user action** over multiple competing asks.
4. **Calm premium pacing** over attention-scramble UI.

## Interface Heuristics

### Layout
- Prefer generous spacing, clear section boundaries, and low visual noise.
- Use strong fold-level structure: each section should answer one user question.
- Avoid dense dashboards on top-level landing experiences.

### Typography
- Display serif for meaning and gravitas.
- Sans body for readability and speed.
- Optional Devanagari for culturally meaningful micro-moments only.

### Color & Surfaces
- Deep indigo base with saffron/orange primary action and gold accents.
- Glass-like dark cards for premium depth.
- Accents must be sparse and intentional.

### Motion
- Subtle fades, float/pulse micro-motion, and soft hover transitions.
- Motion should reinforce orientation and depth, never become spectacle.

### Conversion UX
- Primary CTA is consistent across header, hero, and closing section.
- Secondary links are educational paths, not competing conversions.
- Proof appears before hard asks.

## Anti-Patterns to Avoid

- Guru-marketing claims and sensational “power unlock” language.
- Overusing bright accents that break contemplative tone.
- Multiple equally loud CTAs in one viewport.
- Aggressive popups that interrupt reading before trust is formed.

## Output Template (Implementation-Ready)

When asked for UI direction, return:

1. **Screen intent** (what this section/page must achieve)
2. **Hierarchy map** (headline, support, proof, action)
3. **Component stack** (ordered list)
4. **Token usage** (color/type/spacing/motion)
5. **Responsive notes** (mobile-first constraints)
6. **Accessibility checks** (contrast, focus, keyboard, semantics)
