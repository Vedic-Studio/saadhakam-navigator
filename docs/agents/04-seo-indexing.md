## SEO Library

All SEO utilities are in `src/lib/seo/index.ts`.

Key exports:
- `buildArticleMetadata(params)` — builds Next.js `Metadata` object for articles
- `buildCanonicalUrl(route)` — returns `https://www.opensadhaka.com/<route>`
- `buildUrl(path)` — same as above
- `SITE_URL`, `SITE_NAME`, `SITE_TWITTER`

**Always use these helpers** — never hand-roll `<meta>` or canonical URL strings.

## Metadata Standards

### Title Format
```
{Page Title} | Sadhaka
```
- Max 60 chars total (including " | Sadhaka")
- Primary keyword near the front
- No keyword stuffing — write for humans first

### Description
- 150–160 characters
- Include primary keyword naturally in first sentence
- End with a value proposition or call to understanding
- No generic filler ("Learn everything about X...")

### Canonical URLs
- Always absolute: `https://www.opensadhaka.com/<slug>`
- No trailing slash (`trailingSlash: false` in next.config.ts)
- Use `buildCanonicalUrl("/<slug>")` from the SEO lib

### Open Graph
- `og:image` — use `/og-default.png` if no custom image
- `og:type` — `"article"` for blog posts, `"website"` for index/hub pages

## JSON-LD Schemas

### Article Schema (all editorial articles)
```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "...",
  "description": "...",
  "author": { "@type": "Organization", "name": "Sadhaka" },
  "publisher": { "@type": "Organization", "name": "Sadhaka", "url": "https://www.opensadhaka.com" },
  "datePublished": "YYYY-MM-DD",
  "dateModified": "YYYY-MM-DD",
  "mainEntityOfPage": { "@type": "WebPage", "@id": "https://www.opensadhaka.com/<slug>" }
}
```

### FAQPage Schema (add to articles with FAQ sections)
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Question text?",
      "acceptedAnswer": { "@type": "Answer", "text": "Answer text." }
    }
  ]
}
```

### For Stotra/Verse pages: use `WebPage` + `BreadcrumbList`

## Sitemap

File: `src/app/sitemap.ts`

The sitemap is auto-generated by Next.js from this file. When adding new content:

1. **New stotra**: add to the stotras array in `sitemap.ts`
2. **New article**: articles are added via `src/data/articles.ts` — the sitemap reads from there
3. **New pSEO route type**: add the loader call and URL generation to `sitemap.ts`

Priority values:
- Home: `1.0`
- Hub articles: `0.9`
- Spoke articles: `0.8`
- Stotra index pages: `0.8`
- Verse/name pages: `0.7`
- pSEO pages: `0.7`

Change frequency:
- Articles: `monthly`
- Stotras: `monthly`
- Verse pages: `yearly` (content is stable)

## IndexNow Submission

**When to run**: after every batch of new pages goes live on Vercel.

```bash
npm run indexnow:submit:prod
```

This calls `scripts/submit-priority-indexnow.mjs`, which reads from `scripts/indexnow-priority-config.mjs` and submits URLs to IndexNow (picked up by Bing and Yandex; Google has its own crawl).

### After Publishing New Content
1. Merge to `main` → Vercel auto-deploys
2. Confirm deployment is live
3. Run `npm run indexnow:submit:prod`
4. Check `npm run indexnow:check:prod` to verify submission

### Adding URLs to Priority Config
Edit `scripts/indexnow-priority-config.mjs` — add new slugs to the appropriate priority tier.

## LLM Architecture (GEO / AI Engine Discoverability)

Sadhaka uses a dual-layer architecture: structured HTML for traditional search, explicit machine-readable files for AI engine ingestion (Perplexity, ChatGPT browsing, Claude, RAG pipelines).

### Files

| Route | Type | Purpose |
|-------|------|---------|
| `/llms.txt` | Static file (`public/llms.txt`, generated by `npm run llms:generate`) | AI sitemap — lists all content grouped by type with descriptions; auto-generated from `articles.ts` |
| `/llms-full.txt` | Static file (`public/llms-full.txt`, generated by `npm run llms:generate`) | Bulk content dump — concatenates all article FAQs, BG Shlokas, stotra verses, sahasranama names, and entity summaries into a single chunkable Markdown file |
| `/api/llm-content` | Route Handler (`src/app/api/llm-content/route.ts`) | Per-entity Markdown: `?type={type}&slug={slug}` — structured Markdown for any philosophy, tradition, text, concept, practice, great, topic, or comparison |

Both `/llms.txt` and `/llms-full.txt` set `Cache-Control: public, max-age=86400` — CDN-cached on Vercel.

### When to Update

- `/llms.txt` auto-updates whenever `articles.ts` changes — no manual edit needed
- `/llms-full.txt` auto-updates whenever any data file changes — no manual edit needed
- **If you add a new pSEO content category**: update the generator `scripts/generate-llms-txt.mjs` and re-run `npm run llms:generate`
- **If you add a new stotra/sahasranama**: automatically included via `loadStotra()`/`loadSahasranama()` — no change needed

### Verification After Deploy
```bash
curl https://www.opensadhaka.com/llms.txt | head -20
curl https://www.opensadhaka.com/llms-full.txt | head -50
```

## AEO (AI Engine Optimization)

AEO is about getting Sadhaka content cited as answers by ChatGPT, Perplexity, Claude, Gemini.

### Requirements for every page
1. **Direct answer block** at the top — 60–100 words, plain prose, directly answers the primary query
2. **Structured headings** — H1 exact matches the primary keyword; H2s match common question variants
3. **FAQ schema** — structured data that AI engines can extract directly
4. **Concise definitions** — key Sanskrit terms defined inline in ≤20 words
5. **Source citations** — name the Purana/text. AI engines prefer citable sources.
6. **Machine-readable content** — article FAQs registered in `articles.ts` flow automatically into `/llms-full.txt`

### AEO Audit Checklist
For each page:
- [ ] AEO block present and ≤100 words
- [ ] AEO block is plain prose (no bullets)
- [ ] H1 matches primary keyword intent
- [ ] FAQ schema JSON-LD present if page has FAQs
- [ ] Canonical URL correct and absolute
- [ ] meta description 150–160 chars
- [ ] Article FAQs registered in `articles.ts` (feeds `llms-full.txt` automatically)
