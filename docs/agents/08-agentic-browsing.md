# Agentic Browsing Agent

# Module: Agentic Browsing (Lighthouse)

This module governs **AI-agent operability** for opensadhaka.com — making the
site usable by autonomous browsing agents (ChatGPT Operator, Gemini, Claude for
Chrome, etc.), not just citable by answer engines.

It tracks Chrome's **Lighthouse "Agentic Browsing"** audit category, which moved
from experimental into the default config in Lighthouse 13.3.0 (May 2026).

- Scoring reference: https://developer.chrome.com/docs/lighthouse/agentic-browsing/scoring
- llms.txt reference: https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt

> Note: this category has **no 0–100 score**. It emits a fractional pass ratio
> plus per-audit **pass / fail / N/A / informational** signals. The goal is to
> pass as many checks as possible, not chase a number.

## The four pillars

| Pillar | What the audit wants | Our status | Where it lives |
|--------|----------------------|------------|----------------|
| **1. llms.txt** | Machine-readable Markdown summary at the domain root (`# Title` → `>` summary → `##` sectioned link lists). 404 → N/A; server error → fail. | ✅ Strong | `public/llms.txt` + `public/llms-full.txt`, generated by `npm run llms:generate` (`scripts/generate-llms-txt.mjs`). Source of truth — **not** a route handler. |
| **2. Accessibility tree** | Every interactive element has a programmatic name (button text or `aria-label`; inputs with `<label>`/`aria-label`; custom controls with ARIA). Valid roles + parent/child relationships. Interactive content not hidden from the a11y tree. Agents use the a11y tree as their primary data model. | 🟡 Mostly good (Shadcn/Radix primitives) | Component layer. Static `<img alt>` coverage gated by `npm run agentic:check`. |
| **3. Layout stability (CLS)** | CLS < 0.1. Images/media declare `width`/`height` (or `fill`/aspect-ratio) so elements don't move between the moment an agent locates them and the moment it clicks. | 🟡 Partial | `npm run agentic:check` flags raw `<img>` without a reserved box. Prefer `next/image`. |
| **4. WebMCP** | Page registers callable tools via the draft `navigator.modelContext` API (declarative or imperative). | 🟢 Experimental probe | `src/lib/webmcp.ts` (pure, tested) + `src/components/WebMCPProvider.tsx` (feature-detected, mounted in `src/app/layout.tsx`). No-op on browsers without the API. |

## Tasks

- After content changes: `npm run llms:generate` (keeps pillar 1 fresh).
- Before committing UI changes: `npm run agentic:check` (pillars 2–3 static scan).
  Use `npm run agentic:check:strict` to fail on any finding (CI/gate use).
- New interactive components: icon-only buttons need a visible label or
  `aria-label` / `sr-only` text; form inputs need an associated `<label>`.
- New images: use `next/image` with `width`/`height`, or a raw `<img>` with
  explicit `width`/`height`, or an `object-cover` image inside a height-reserved
  parent. Never ship a full-width `<img>` with auto height above the fold.

## Conventions

- The static `public/llms.txt` / `public/llms-full.txt` are canonical and win
  over any App Router route. Do **not** reintroduce `app/**/llms.txt/route.ts`
  handlers — they shadow-conflict with the generated files.
- WebMCP is a moving draft. Keep `webmcp.ts` feature-detected and side-effect
  light; never let tool registration throw into the page.

## Verify (runtime — needs a real browser)

The static checker covers what source analysis can see. For the full audit:

1. `npm run build && npm run start`
2. Chrome DevTools → Lighthouse → enable **Agentic Browsing** category → analyze
   a representative set: homepage, an article, a deity page, a stotra page.
3. Confirm: llms.txt audit passes, a11y-name audits pass, CLS < 0.1, and the
   WebMCP audit reflects registered tools (where the API is available).
